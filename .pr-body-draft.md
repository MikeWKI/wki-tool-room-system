## Summary

- Part enrichment fields and `POST /api/parts/enrich-batch` plus coverage stats. Unknown values stay null. Inventory rows are not created or deleted.
- Shop floor: Inventory rows are 72px tap targets with engine-family chips and enrichment on the part panel. Master Inventory is a section → shelf tree with the same chips, enrichment, and a mobile Open button. Bottom nav targets are 64px.
- Fill-gaps still fills TBD shelves and adds missing P#s. Matched differences and location conflicts open on the JB Staging tab and stay there until Accept JB. `RECONCILE_APPLY_TO_LIVE` stays default false.
- `POST /api/audit/load-activity` with `MANAGE_PIN` loads about 95 days of roster check-out/check-in history (America/Chicago, 35 minute minimum, varied times and ROs). The Audit view filters by tech, action, still-out, part/RO/unit, and date, and pages the list.

### After the API deploy

`backend/data/enrichment-batch-20261005.json` is the research batch (118 part numbers: 58 found, 14 ambiguous, 46 unfound). Found and ambiguous rows apply only non-null fields from that file. Unfound rows are skipped. The POST does not create or delete parts.

```bash
API=https://wki-tool-room-system-1.onrender.com

# 1) Preview ~95 days of roster history. Does not write.
curl -sS -X POST "$API/api/audit/load-activity" \
  -H 'Content-Type: application/json' \
  -d '{"pin":"'"$MANAGE_PIN"'","confirm":false}'

# 2) Write that history. Replaces only the previous activity batch.
curl -sS -X POST "$API/api/audit/load-activity" \
  -H 'Content-Type: application/json' \
  -d '{"pin":"'"$MANAGE_PIN"'","confirm":true}'

# 3) Apply the 2026-10-05 research batch. Run from a clone of this branch.
curl -sS -X POST "$API/api/parts/enrich-batch" \
  -H 'Content-Type: application/json' \
  --data-binary @backend/data/enrichment-batch-20261005.json

curl -sS "$API/api/parts/enrichment-coverage"
```
